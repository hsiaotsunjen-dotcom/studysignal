## 最小架構與重用範圍

1. 跨學科清冊：`subject`、`materialId`、`pageId`、`scanSeq`、`printedPage`、`label`、`pageNumberVerification` 分開保存。圖片、OCR、版面、品質、人工審核、重試錯誤與正式 KB 狀態是不同欄位。
2. 兩個來源 adapter：現有 manifest＋page-index 格式；通用 `canonical-pages-v1` 格式。後者讀取 `{pages:[...]}`，每頁具有 scanSeq、originalFileName、printedPage、label、pageNumberVerification，以及 image 的 path、sha256、bytes、可選 backupPath。化學以合成資料測試；尚未處理真實化學教材。
3. 重用 `kb-ocr-batch.mjs` 的 attempt/retry 與附件雜湊驗證，以及既有 `normalizeText.ts`，未修改舊執行器。
4. 重用 v2.1 `buildSourceAlignment` 建立 raw→TSV 詞框的來源對應，重用科學公式 token 分析。字串一致或公式語法可解析都不代表原圖正確。
5. 重用既有 layout prototype、diagnostics、quality routing，另存三頁的候選版面與風險；沒有覆蓋既有區域設定。
6. 透過 v2.2 `openReviewStore(...).readState(...)` 唯讀讀取掃描 200 工作包，核對來源並記錄 snapshot 雜湊、head、建議數及事件數。13 項建議、0 審核事件、head=null，沒有新增審核／apply／rollback 事件。

本清冊是處理層索引，不修改正式 Knowledge Base schema。正式 KB 發布仍需另外核准與 adapter；本階段以現有稽核的「未正式入庫」為基準，不從 OCR 成功推導入庫成功。整頁品質核准匯入、跨頁閱讀順序及完整表格／概念圖重建尚未實作。

## 追溯、恢復與安全

- 配置、選頁來源 SHA、印刷頁碼、引擎版本、模型 SHA 與執行器版本形成 run fingerprint。來源／引擎／配置變更會拒絕 resume，應建立新版本並引用原有成功頁面。
- 先驗證所有可重用頁面與結果，再允許任何新 OCR。已完成頁面驗證後直接跳過。
- 每頁 `pages/NNNN/attempt-NN/` 保存 started、raw、normalized、TSV、blocks、candidate-result 與成功 result；失敗保留 error。只有來源與附件檢查通過才發布成功標記。
- attempt 目錄不覆寫；中斷但未完成的 attempt 保留，恢復時使用下一個 attempt。預設最多三次，耗盡後保留失敗，不無限重試。
- checkpoints 與 sessions 採 exclusive create，逐筆追加。暫停後重新以相同選頁及配置加 `--resume true` 恢復；batch-size 可變更，頁面處理保持串行。
- `--stop-after N` 可在完成 N 個新頁面後暫停；Ctrl+C／SIGTERM 或 run 內存在 `PAUSE` 檔案時於頁面邊界暫停。PAUSE 檔案不會由工具擅自刪除。
- run.lock 防止雙重執行。異常終止留下的鎖需明確指定 `--recover-stale-lock true`，且 PID 不存在才保留改名舊鎖後恢復；有效 PID 一律拒絕。真實強制終止／Windows PID 重用情境尚未端到端演練。
- EXIF 旋轉非 identity 的新頁面拒絕處理，避免變換後詞框冒充原圖座標；需要日後新增可逆座標轉換 adapter。
- 第一階段 CLI 每次最多選三張未完成 OCR 頁面，輸出限制在專案內獨立 `tmp-ocr-v23-*`。核心支援通用頁碼範圍與批次大小 1–50；沒有開放整本執行。
